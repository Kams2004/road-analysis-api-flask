# VIASafe mobile app — screens, accounts and Google sign-in (implementation spec)

App: `api/viasafe-mobile` (Expo SDK 57, expo-router, React Native 0.86, MapLibre, expo-location, react-native-safe-area-context). Brand stays **VIASafe**. Design reference: the user's 11-screen mockup (described below). Images already cropped into `assets/images/onboarding/{city,hazards,journeys,community}.jpg`, `onboarding/location-map.png`, `assets/images/hazards/{pothole,roadworks,flood,sign}.jpg`.

## Global rules
- **Safe areas everywhere**: every screen uses `SafeAreaView`/`useSafeAreaInsets` (react-native-safe-area-context) so content and bottom bars never sit under the status bar or the Android navigation bar (3-button or gesture). Bottom tab bar and bottom sheets add `insets.bottom`. `app.json`: `"android": { "edgeToEdgeEnabled": true }` is fine as long as insets are respected.
- **Language toggle**: EN / FR segmented pill **centred at the top** of every screen from the splash through onboarding, location permission, login/register, up to the map home (where it stays at the top centre of the map overlay). Tapping switches the whole UI immediately; choice persisted with AsyncStorage (already installed) and synced to the user profile (`PATCH /auth/me {language}`) when signed in. Spanish stays available in Profile → Language (EN / FR / ES).
- **No hard-coded positions**: the user's position always comes from expo-location (`watchPositionAsync`, high accuracy). While no fix is available show a "Locating…" state; never fall back to fixed Douala coordinates for the user dot, routing origin, nearby queries or telemetry. A city-level initial camera before the first fix is fine. Remove any fixed demo coordinates used as the user position.
- All backend calls through `lib/api/config.ts` `apiFetch` (adds `X-API-Key`) and, when signed in, `Authorization: Bearer <token>` (token stored in `expo-secure-store` if available, else AsyncStorage).

## Backend (FastAPI `api/app`) — mobile accounts
- Self-registered users are platform `users` with `account_type = "mobile"` (new column, default `"staff"` for existing rows; add via `app/db/upgrade.py`) and **no roles** (the web console then shows nothing to them). Staff accounts can also sign in on mobile.
- `POST /auth/mobile/register` {full_name, email, password, phone?, language?} — requires a valid API key (the mobile app), password policy, e-mail unique, per-IP rate limit (Redis, e.g. 5/hour), returns the same LoginOut as /auth/login (session token).
- `POST /auth/mobile/login` {identifier, password} — API key required instead of CAPTCHA; same lockout rules/audit as /auth/login; MFA still enforced for staff with MFA (returns mfa_required → `/auth/mfa/verify`).
- `POST /auth/google` {id_token} — verifies the Google ID token (`https://oauth2.googleapis.com/tokeninfo?id_token=…`, check `aud` ∈ configured client IDs, `email_verified`, `exp`), finds the user by e-mail or creates a mobile account (no password), stores `google_sub`; inactive → 403. Returns LoginOut. Usable by web too later.
- Settings section `google_signin` (runtime, Settings → Platform): `enabled`, `web_client_id`, `android_client_id`, `ios_client_id`. Public `GET /auth/config` adds `google: {enabled, web_client_id, android_client_id, ios_client_id}`.
- Principal: when a request carries BOTH a valid `X-API-Key` and a valid user `Bearer` token, the client principal also carries that user (so `reported_by`, votes and `/auth/me` work from the app). `/auth/me`, `PATCH /auth/me`, `/auth/logout` accept that combination.
- Signalements created by a signed-in mobile user store `reported_by = user e-mail` (ignore client-sent value).
- Audit every register/login/google event.
- Tests for register/login/google (mock tokeninfo) and the combined principal.

## Mobile Google sign-in
- Use `expo-auth-session` (+ `expo-crypto`, `expo-web-browser`) Google provider (`Google.useIdTokenAuthRequest`) with client IDs from `GET /auth/config` (fallback `EXPO_PUBLIC_GOOGLE_*` env). Send the id_token to `POST /auth/google`. If not configured, the Google button shows a short "Google sign-in is not configured yet" message instead of failing.
- The Android OAuth client must be created in Google Cloud with package `com.viasafe.mobile` and the SHA-1 of the signing key (debug: `android/app/debug.keystore`).
